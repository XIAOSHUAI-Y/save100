# 100万打卡（网页版）

存钱目标打卡工具。照微信小程序「100万打卡」的「方格」页 1:1 复刻，
其余页面（存折 / 便签 / 报告 / 主题 / 活动）在原 App 里要充 VIP 才能看，
这里全部免费开放，数据存本机浏览器。

## 跑起来

```bash
npm install
npm run dev      # http://localhost:5190  手机同 Wi-Fi 用 http://<你的内网IP>:5190
npm test         # 模型层单测
npm run build    # 产物在 dist/，丢给任意静态服务器即可
```

手机访问：`vite.config.ts` 里 `server.host` 已开，终端会打印 Network 地址，
用手机浏览器打开那个地址就行；想长期用可以在浏览器里「添加到主屏幕」。

## 页面

| 路由 | 内容 |
| --- | --- |
| `#/grid` | 方格：已攒 / 剩余格 / 已点亮三张卡 + 进度条 + 网格（**点哪格亮哪格**，每行格数可拖） |
| `#/passbook` | 存折：按月分组的流水，点一行可改金额 / 日期 / 备注、可删 |
| `#/notes` | 便签：随手记，可置顶 / 编辑 / 删除 |
| `#/report` | 报告：近 30 天、连续打卡、日均速度、预计达成 + 最近 6 个月柱状图 |
| `#/themes` | 主题：6 套配色 |
| `#/activities` | 活动：52 周存钱法、365 天存钱法、阶梯冲刺 |
| `#/vip` | 设置：目标名称 / 目标金额 / 每格金额、导出导入、清空 |

目标金额和每格面值都可以自己改：格子下方有一行「目标 10万 · 每格 500 元 · 修改」直达，
顶栏 `⋯` 或 `2026目标 ›` 也进同一页。格数 = 目标金额 ÷ 每格金额（四舍五入），
改完立刻重算米字格；除不尽时最后一行补透明空位。

### 里程碑卡片

点亮第 **1 / 10 / 50 / 100** 格，之后每 **100** 格各解锁一张「恭喜达成」卡片
（格数不够就自动不出，200 格时是 1/10/50/100/200）。

- 全屏遮罩 + 撒花 + 卡片进场，轻触翻面：正面是图标和「第 N 格」，背面是解锁条件、一句语录、解锁日期
- 解锁记录存在 `state.unlocked`，一张卡只弹一次
- 一次存入跨过多个里程碑时排队：关掉第一张不是淡出重来，而是**再翻 180° 换下一张**——
  卡片转到侧面（90°）那一刻两面都看不见，就在这瞬间换内容，看起来就是「翻过去是新的一张」
- 颜色全部走主题变量（`--on-strong` / `--on` / `--off` / `--accent-soft` / `--card` / `--text`），
  撒花也从这几个变量取色，换主题整体跟着变
- 「已点亮方格」卡片可以点开里程碑列表，已解锁的能重看，未解锁的显示还差几格

### 格子大小

格子大小 = 容器宽度 ÷ 每行格数，所以可调的是「每行几格」（8~30，默认 20）：
格子卡里那条滑块就是。拖动时只改 CSS 变量 `--cols`（实时预览），
松手才写存储——每拖一格就重渲染 200 个按钮，手机上会卡。

`--cols` 同时决定格子编号：编号永远是阅读顺序，换行数不影响「第 N 格」的含义。

### 方格是独立点亮的

**点哪一格亮哪一格**，一格 = 存了「每格金额」。不是按总额从某个方向累加出一段前缀。

每笔存入带 `cells` 数组记录它点亮了哪几格：

- 点空格子 → 新建一笔 `每格金额` 的存入，`cells=[那一格]`
- 再点已亮的格 → 取消点亮，从那笔里摘掉这一格、金额同时减掉一格；减到 0 就删掉这笔
- 「打卡」存一个任意金额 → 按阅读顺序（左上→右下）点亮前 `floor(金额/每格)` 个空格；
  格子不够时直接拦住，提示还能存多少
- **长按拖选**：按住一格约 240ms 进入选择模式（震动一下 + 底部出现「点亮 N 格 · ¥X」），
  手指划过哪些格子就选中哪些，松手一次性记成一笔 `N × 每格金额` 的存入。已经亮了的格子会跳过。
  拖选期间会拦住页面滚动，所以不会一拖就滑走
- **长按拖选取消**：按在**已点亮**的格子上进入取消模式（格子淡下去、提示变成「取消 N 格」），
  划过的已亮格子松手后一起取消，金额按格数退回；一笔减到 0 就把那笔记录删掉。
  两种模式由起手那格是否已亮决定，不额外加开关

所以金额和格数永远对得上，不会出现「攒了几万却一格没亮」。
老版本（格子前缀那套）的数据没有 `cells` 字段，读取时会按金额自动补点亮格，不会丢。

### 为什么拖选要长按

方格区很长，直接拖会和页面滚动抢手势。所以先用 240ms 长按（此时手指还没动）确认意图，
进入选择模式后才 `preventDefault` 拦滚动。鼠标没有这个冲突，拖过 8px 就直接进入选择。
实现在 `src/dragselect.ts`，只挂在方格容器上，单击仍然走原来打开单格弹层的路径。

### 撤销

点亮、取消点亮、打卡、改金额、删记录这些动作都是立刻生效的，改完底部会浮一条提示，
4 秒内可以点「撤销」回到改之前。

- 实现在 `src/undo.ts`（提示条）+ `store.undo()`（放回快照）
- 快照只留**一份**，就是上一次改动前的 `deposits`；连做两次只能退回一步
- 只回滚存入数据，不回滚里程碑的「已解锁」记录——已经弹过的卡片不会再弹
- 导入 JSON / 清空数据之后旧快照失效

## 图标与开屏

形象是「攒钱罐」：玻璃罐 + 三枚金币 + 笑脸。同一套图形出现在三个地方。

| 文件 | 用途 |
| --- | --- |
| `public/icon-180.png` | iOS 添加到主屏幕（apple-touch-icon，系统自己切圆角） |
| `public/icon-192.png` / `icon-512.png` | `manifest.webmanifest`，安卓 / PWA |
| `public/favicon.svg` | 浏览器标签页，内嵌 CSS 动画（Chrome 会动，Safari 停在一帧） |
| `src/splash.ts` + `.splash` 样式 | 打开 App 时的开屏动画 |
| `design/icon-jar.svg` / `icon-jar-master.png` | 母版，改图形从这里改 |

**桌面图标本身不会动**——iOS / 安卓的桌面图标都是静态图。所以动画放在开屏：
`showSplash()` 在首次加载时盖一层，罐子左右晃、金币上浮、眨眼，850ms 后淡出
（320ms）。`prefers-reduced-motion: reduce` 下直接不显示；切路由不会重复播放。

**iOS 换图标要先删掉桌面上的旧图标再重新添加**，否则读的是系统缓存的旧图。

改图标流程：改 `design/icon-jar.svg` → 用浏览器按 1024 截图 → 缩出 180/192/512。
第一版方格图标和 10 个候选方案的图在 `design/variants/` 里，只作留档，不进构建产物。

## 版本更新提醒

改完代码重新部署后，还开着旧页面的人（主要是自己手机）需要知道有新版本。

- **怎么知道有新版本**：构建时 `vite.config.ts` 会把 `__BUILD_ID__` 打进 JS，同时产出
  `dist/version.json`（`{version, buildId, builtAt}`）。运行时拿服务器上的 buildId 和自己
  那份比，不一样就是有新版本。dev server 由同一个插件提供 `/version.json`，两边一致，
  所以开发时不会弹。
- **什么时候查**：打开 4 秒后查一次；之后每 5 分钟查一次；切回前台（且距上次检查超过 60 秒）
  查一次；网络恢复时查一次。切路由不查。
- **提示**：底部浮出「新版本已准备好」+「立即更新」，右上角 ✕ 是「稍后」（按 buildId 记住，
  同一个版本的提示不会反复弹）。手动入口在**主题页最下面的「检查更新」**，点开有
  正在检查 / 已是最新 / 发现新版本 / 检查失败 四种状态。
- **更新做了什么**：没有 Service Worker，所以就是带着 `?v=<buildId>` 重新加载一次
  index.html，拿到新的带哈希资源；加载后把 `?v=` 从地址栏清掉，hash 路由不受影响。
  **数据全在 localStorage，刷新不影响**。

## 部署

线上地址：https://xiaoshuai-y.github.io/save100/

GitHub Pages 从 `gh-pages` 分支根目录发布，`master` 只放源码。

```bash
npm run deploy    # 构建 + 把 dist 推到 gh-pages
```

几点约束：

- 构建时 `base` 是 `/save100/`（子路径），dev 仍是 `/`，所以本地开发网址不变。
- **没有加 GitHub Actions**：当前 `gh` token 缺 `workflow` 权限，推不了
  `.github/workflows/`。想改成 push 即部署，先 `gh auth refresh -h github.com -s workflow`
  再加 workflow，然后把 Pages 的 Source 切到 GitHub Actions。
- `.nojekyll` 由部署脚本自动生成，避免 Jekyll 处理静态文件。
- **数据不跨域名**：`localStorage` 按 origin 隔离，`192.169.1.138:5190` 上的记录不会自动
  出现在线上。换到线上时用 App 里的「导出 / 导入」搬一次。

## 数据

全部在 `localStorage` 的 `save100.state.v1`：

```ts
{ version: 1,
  settings: { goalName, target, cellValue, startDate, theme, cols },
  deposits: [{ id, date: 'YYYY-MM-DD', amount, note, createdAt, cells: number[] }],
  notes:    [{ id, text, createdAt, pinned }],
  unlocked: { '1': 'YYYY-MM-DD', '10': 'YYYY-MM-DD' } }
```

`cells` 里的编号是阅读顺序：左上角 = 0，往右递增。

只在本地，不联网、没有后端。**换手机或清缓存前先在 VIP 页导出 JSON**。

## 几条实现约束（改的时候别踩）

- **派生数字只从 `derive()` 算**。已攒 / 剩余格 / 点亮格 / 进度全在 `src/model.ts`，
  各处自己拍数字必然互相打架。
- **日期一律用本地时区的 `YYYY-MM-DD`**（`todayStr()`），不能用 `toISOString()`
  —— 那是 UTC，东八区凌晨会差一天，跨天打卡直接算错。
- **格数 = round(target / cellValue)**。改目标金额或格子面值后格数会变，
  网格列数固定 20，行数按格数向上取整，余数补透明格；变小后越界的 `cells` 会被清掉。
- **点亮/取消点亮必须和金额同步**：取消时从 `deposits` 里减掉一格的钱，不能只把格子抹掉，
  否则「已攒金额」和「已点亮格数」会各说各话。
- `money()` 保留两位（8.40万），`shortMoney()` 去尾零（2.5万 / 5万 / 500元）。
  刻度条和「距 X 目标」用后者，卡片大数字用前者——参考 App 就是这么分的。
- 主题只改 CSS 变量，组件里不许写死颜色。
